● Guia do repositório

Como usar os dados

Este repositório baixa os microdados do BADEPI, organiza-os em camadas (bronze → silver → gold) e publica este painel. Tudo em Python, com pandas e parquet, reproduzível em qualquer máquina.

Fonte

O que é o BADEPI

A Base de Dados de Propriedade Intelectual (BADEPI) é mantida pela Coordenação-Geral de Economia e Inovação do INPI em cooperação com a OMPI. Reúne, para fins estatísticos, os registros administrativos de cada ativo de PI, com série histórica de 2000 a 2025 e dados pessoais limitados conforme a LGPD. É atualizada uma vez por ano; a versão 12.0 saiu em 13/10/2026.

Cada ativo é um arquivo zip com CSVs (separador ;, CRLF, encoding misto latin-1/UTF-8) e um dicionário de microdados em XLSX. Patentes tem sete tabelas; marcas, quatro; desenhos, cinco; IG, quatro.

Arquitetura

Camadas medalhão

Bronze

Os zips e CSVs exatamente como o INPI publicou, com manifesto (URL, SHA-256, tamanho, data). Nada é alterado. data/bronze/<ativo>/

Silver

Parquet tipado e limpo: chaves sem espaços, datas reais, vazios como nulos, colunas derivadas (origem, via, situação) e dimensões para relacionamento. data/silver/<ativo>/

Gold

Agregações prontas para visualização em JSON pequenos, copiados para docs/data/ e servidos pelo GitHub Pages. data/gold/<ativo>/

Rodar

Do zero ao painel em quatro comandos

Requisitos: Python 3.11+ e uv. O download completo tem cerca de 500 MB (3 GB extraídos); só patentes são ~130 MB.

Instale as dependências
git clone https://github.com/Jaimenms/badepi-dashboard.git
cd badepi-dashboard
uv sync
Bronze — baixe e extraia (todos os ativos, ou só os desejados com -s)
uv run badepi bronze                      # os 8 zips
uv run badepi bronze -s patentes -s pi_genero
Silver — transforme em parquet (patentes ~1 min; marcas ~1,5 min e 6 GB de RAM)
uv run badepi silver -s patentes -s marcas -s desenho_industrial -s indicacao_geografica
Gold — gere os JSON do painel e sirva o site localmente
uv run badepi gold                       # todos os ativos prontos + comparativo
python -m http.server -d docs 8000      # abra http://localhost:8000
Atalho: uv run badepi all -s patentes -s pi_genero executa bronze → silver → gold. Use --force para refazer uma camada já construída. A variável BADEPI_DATA_DIR muda a pasta dos dados.

Para publicar: faça push na main. O workflow .github/workflows/pages.yml publica a pasta docs/ (em Settings → Pages, escolha Source: GitHub Actions).

Tabelas silver

Em todos os ativos as tabelas se relacionam pela chave no_pedido; cada ativo tem um fato <prefixo>_deposito (1 linha por pedido, com origem e colunas derivadas) e uma <prefixo>_situacao (situação e marcos), mais depositantes, despachos, classes e dimensões. Pandas

Consultando a silver

Os arquivos são parquet comuns: qualquer ferramenta lê. Com pandas, o helper read_parquet do pacote cuida do dataset particionado de despachos e preserva os tipos nullable.

import pandas as pd
from badepi.ioutil import read_parquet

S = "data/silver/patentes"
dep = read_parquet(f"{S}/ptn_deposito.parquet")
sit = read_parquet(f"{S}/ptn_situacao.parquet")
df  = dep.merge(sit, on="no_pedido")

# pedidos de residentes por UF e situação
(df[df.residente]
   .pivot_table(index="uf_origem", columns="situacao", values="no_pedido", aggfunc="size", fill_value=0)
   .sort_values("Concedida", ascending=False)
   .head(10))

# tempo mediano até a concessão por campo tecnológico (concessões desde 2020)
dim = read_parquet(f"{S}/dim_campo_tec.parquet")
rec = df[df.dt_concessao >= "2020-01-01"]
(rec.groupby("campo_tec_principal").anos_ate_concessao.median()
    .rename("mediana_anos").to_frame().join(dim.set_index("campo_tec")).sort_values("mediana_anos"))

# despachos de 2024 em diante (lê só as partições necessárias)
desp = read_parquet(f"{S}/ptn_despacho", filters=[("ano_publicacao", ">=", 2024)])
desp.evento.value_counts().head(10)

# inventores e inventoras de um pedido
inv = read_parquet(f"{S}/ptn_inventor.parquet")
inv[inv.no_pedido == "102012000050"][["no_ordem", "nome", "uf", "cidade"]]
Volumes: ptn_despacho tem 3,9 milhões de linhas e por isso é particionada por ano_publicacao (formato hive). Use o argumento filters ou leia só as colunas necessárias com columns=[...].
Método

Como a situação de um pedido é derivada

Os 304 códigos de despacho da RPI são mapeados para ~25 eventos (depósito, publicação, exigência, parecer, deferimento, indeferimento, concessão, arquivamento, desarquivamento, restauração, extinção, recurso, recurso provido, nulidade, transferência, trâmite prioritário, licença…). O mapeamento está em src/badepi/silver/patentes.py e a tabela dim_despacho traz o resultado por código.

A situação de cada pedido usa a última data de cada tipo de evento, nesta ordem:

  1. Houve concessão (16.1)? Então é Anulada se houve anulação posterior (16.4/200), Extinta se a última extinção (21.x, 24.x) é posterior à última restauração, senão Concedida.
  2. Desistência ou retirada homologada posterior a qualquer decisão → Retirada.
  3. Indeferimento (9.2) não revertido por recurso provido (100.x) nem seguido de deferimento → Indeferida.
  4. Arquivamento (8.6, 11.x…) não revertido por desarquivamento/restauração → Arquivada.
  5. Deferimento (9.1) sem concessão ainda → Deferida.
  6. Caso contrário → Em andamento.

Além disso, ptn_situacao guarda os marcos (primeira publicação, primeira exigência, primeiro parecer, deferimento, indeferimento, concessão, último arquivamento e extinção), o fim de vigência legal (20 anos para PI/CA, 15 para MU, contados do depósito), a flag prazo_expirado e os tempos anos_ate_concessao e anos_ate_decisao.

Outras derivações

  • Natureza pelo prefixo do número: PI/10/11/12 → PI; MU/20/21/22 → MU; C/13 → CA.
  • Via PCT: prefixo 11/21, presença em ptn_pct ou despacho 1.1/1.3.
  • Origem: país/UF/categoria do depositante de ordem 1 (regra do manual do BADEPI).
  • Campo tecnológico principal: campo da IPC de ordem 1; se ausente, o primeiro campo informado.
  • Categoria do depositante: expressões regulares sobre o nome normalizado (universidade, instituto de pesquisa, governo, empresa) + tipo de pessoa (F/J) informado para residentes. Pedidos em sigilo chegam sem nome → "não identificado".

Despachos de marcas e de desenhos

O BADEPI não traz a descrição dos despachos de marcas (só os códigos DESP###, usados até 2013, e IPAS###, desde então). Os códigos decisivos foram identificados em publicações da RPI — publicação para oposição (003/IPAS009), oposição (IPAS423), exigência de mérito (IPAS142/136), deferimento (351/IPAS029), registro (400/IPAS158), arquivamento por falta de pagamento (150/IPAS157), indeferimento (100/IPAS024), recurso (IPAS360/237/235), extinção (IPAS161), petições (IPAS270/271/428) — e estão em silver/marcas.py; os demais entram como "outros". Em desenhos industriais, os códigos do sistema novo (fim de 2023) também vêm sem descrição e foram inferidos pela cronologia: 860 depósito, 158 registro, 870 prorrogação, 136 exigência, 139 arquivamento, 270 petição deferida, 1214/1233/1252 trâmite via Haia.

Ciclo de vida e grafo de transições

O ciclo de vida calcula, para cada pedido, o estado a cada meio ano decorrido desde o protocolo (depositado → publicado → vigente / indeferido / arquivado / retirado → extinto ou expirado), usando só os pedidos já observáveis naquele ponto. O grafo de transições conta, dentro de cada pedido, os pares de despachos consecutivos (a → b) por ano de depósito; os 45 códigos mais frequentes viram nós e os demais são somados em "OUTROS".

Problemas conhecidos da fonte (v12)

  • DT_PEDIDO_ORIGEM em prioridades repete o número da prioridade: as datas ficam nulas.
  • Seis pedidos com número inválido (erro1…erro5, 0) e datas-sentinela (0001-01-01, 2099-01-01, 1111-11-11), tratadas como nulas.
  • Encoding misto: a maioria das tabelas está em cp1252, despacho em UTF-8, e há linhas isoladas no outro encoding; a leitura decodifica linha a linha.
  • ~6% dos pedidos não têm classificação IPC; ~1.500 pedidos por ano não têm nome de depositante (nunca publicados).
